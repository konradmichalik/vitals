# AGENTS.md

## Project overview

Vitals is a macOS tool that correlates system metrics with the local dev toolchain (DDEV, Docker, OrbStack, Time Machine, Claude CLI sessions) and reports named findings instead of raw graphs. It ships as a Rust CLI (`vitals`) and a SwiftUI menubar app that shares the same Rust core.

- Rust workspace, edition 2021, MIT licensed. `vitals-core` is macOS-only (probes shell out to `sysctl`, `vm_stat`, `tmutil`, `ps`, `ddev`, `docker`)
- Menubar app: Swift 6, SwiftUI, deployment target macOS 14.0, project generated by XcodeGen
- Early development, breaking changes are expected

## Structure

- `core/`: `vitals-core` crate. `probes/` (one module per data source), `rules.rs` (rule engine), `actions.rs` (`Action` enum, `--fix` targets), `config.rs` (`~/.vitals.toml`), `types.rs` (JSON contract), `report.rs`
- `cli/`: the `vitals` binary. Flag parsing, confirmation prompts and output formatting only, no probe logic
- `app/vitals-ffi/`: root workspace member, C ABI (`vitals_collect`, `vitals_free_string`) linking `vitals-core` directly
- `app/VitalsApp/`: SwiftUI target (`Bridge/`, `Models/`, `Support/`, `Views/`)
- `app/VitalsAppTests/`: XCTest target
- `app/project.yml`: XcodeGen source of truth, never hand-edit `VitalsApp.xcodeproj`
- `docs/DEVELOPMENT.md`: deeper notes on probes, rules, actions, JSON contract and app signing

## Development commands

```bash
cargo build --workspace
cargo test --workspace
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings

make -C app xcode        # cargo build vitals-ffi, then xcodegen generate
make -C app test         # xcodebuild test (a plain build does not run tests)
make -C app lint-swift   # swiftlint lint --strict
make -C app lint         # lint-rust (fmt, clippy on vitals-ffi) and lint-swift
```

The Swift side needs `xcodegen` and `swiftlint` (`brew install xcodegen swiftlint`).

## Testing

- Rust: unit tests live next to the code. Probe tests use captured real command output as fixtures, not mocked shell calls. Every rule has a fixture-based test in `rules.rs`
- Swift: XCTest in `app/VitalsAppTests/`, covering the pure functions (decoding, poll interval, argument building, traffic light, alert transitions)
- Write the test first and confirm it fails before implementing
- CI (`.github/workflows/ci.yml`, macOS runners, on push to `main` and pull requests): job `rust` runs `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`. Job `swift` runs `make -C app test` and `make -C app lint-swift`
- Tagged releases (`v*`) build the CLI and app per architecture via `.github/workflows/release.yml`

## Code style and linting

- Rust: `rustfmt.toml` sets `max_width = 100`. Clippy warnings fail CI
- Swift: `app/.swiftlint.yml` with `--strict`. Line length 150 warning, function body 50 lines warning, no force unwrapping (opt-in rule)
- Slow or hang-prone probes must use `probes::shell::run_with_timeout` with an explicit timeout, never plain `run`
- New config fields need `#[serde(default)]`
- Bump `SCHEMA_VERSION` in `core/src/types.rs` on any breaking change to the `vitals --json` shape
- Add a name to `ACTION_NAMES` in `core/src/actions.rs` when adding an `Action` variant
- `app/VitalsApp/Bridge/vitals.h` is generated by cbindgen, gitignored, never hand-edited
- The app is ad-hoc signed (`CODE_SIGN_IDENTITY: "-"`), no Apple Developer account is used

## Git workflow

- Commit format: `<type>: <description>` with type one of `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`
- Describe the change, not what prompted it
- No co-author trailers
